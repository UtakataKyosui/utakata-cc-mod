# verification-gate

受け入れ条件ごとに検証コマンドを実行し、終了コードと作業ツリーの状態から完了判定の証跡を提供する。

## 前提

検証に使用するCLIと、変更状態を取得するためのGitが必要。Git管理外ではコマンドが成功しても、再変更の有無を判断できないため未検証扱いになる。

## 使い方

1. `mcp__verification-gate__verify_define` で条件を登録する。
2. 必要なら変更前に `verify_run` を `{"baseline":true}` で実行する。
3. 変更後に `verify_run` を `{}` で実行する。
4. `verify_status` または `/verification` で現在の状態を確認する。

登録例（ツールへの入力）:

```json
{"conditions":[{"id":"tests","description":"既存テストが通る","command":["pnpm","test"],"timeout_sec":300}]}
```

条件は最大20件、idは英数字・_・-で40文字以内。commandはシェルを介さないargv配列。再登録は条件全体を置き換え、実行記録を消す。`verify_run` にidを渡すとその条件だけを実行する。省略時は全件を順番に実行する。

## 判定と保存

成功、失敗、未実行、タイムアウト、検証不可、成功後の再変更を区別する。変更前の成功後に失敗すれば回帰、変更前と同じ終了コードの失敗なら既存の失敗として表示する。既存の失敗も成功には数えない。

条件と実行時刻・終了コード・所要時間・変更状態をプラグインstoreにプロジェクトルート単位で保存する。出力本文は保存せず、失敗時だけ末尾をモデルへ返す。

## 失敗ログのローカルLLM抽出

失敗した検証コマンドの出力は、既定ではこれまでどおり末尾 `outputTailChars` 文字を返す。エラーが末尾より前にある場合に備え、`llmMode` でローカルLLM(ollama)による抽出を有効にできる。共通基盤は [shared/local-llm](../../shared/local-llm/README.md)。

- 出力(標準出力+標準エラー)を最大100000文字まで収集する。超えるときは先頭と末尾の半分ずつを残し、中央は収集しない。
- 収集したログを1行ずつ(1行300文字まで)に分けて行IDを付け、LLMには関係する行のID(エラー・失敗したテスト・前後の関連行、60件まで)だけを選ばせる。LLMは本文を書かない。
- 返すのは選ばれた行の原文で、`L<行番号>: 本文` の形に組み立てる。行番号は収集したログ内の番号。離れた行の間は `…`、収集しなかった中央をまたぐ箇所は省略文を挿入する。返却は `outputTailChars` 文字までで、超えた分は後ろの行から省き、行数を見出しに示す。見出しには、LLMが選んだ抜粋であること、収集上限による切り詰めがあれば明記する。
- LLMへ送る入力は `maxInputChars` に収める。ログが長いときは先頭側と末尾側の行だけを渡し、省略した行数をプロンプトに含める。
- LLMは表示する行の選択にだけ使う。終了コード・タイムアウト・変更状態・成功判定・既存失敗や再変更の判定は従来の決定的な処理のままで、記録の確定後に行い、結果は一切影響しない。成功・タイムアウト・実行不可の条件ではLLMを呼ばない。
- 入力と応答は参考データ。ログ本文は保存せず、診断記録(デバッグログ)にも理由コード・モデル名・所要時間・文字数だけを書き、本文は残さない。

| llmMode | 動作 |
|---|---|
| `off`(既定) | 通信せず、従来どおり末尾を返す |
| `auto` | 収集したログが `outputTailChars` を超えるとき(末尾だけでは収まらないとき)だけ試す |
| `always` | 失敗した条件ごとに必ず試す |

選択の失敗(接続不能・タイムアウト・不正な応答・範囲外や重複のID・空の選択・入力上限超過・trust-boundaryによる拒否)は、どのモードでも例外にならず、従来の `--- <id> の出力 (末尾) ---` に戻る。ollamaの宛先は trust-boundary の `allowedHosts` に含める必要がある(既定の `http://localhost:11434` は許可される)。

### 追加確認の手順

出力は保存しないので、抜粋の外側が必要なときは次のいずれかで確認する。

1. `verify_run` に失敗した条件の `id` を渡して再実行し、出力の末尾を取得する。
2. 抜粋の行番号を手掛かりに、同じコマンド(`verify_status` や `/verification` が示す `$ ...`)を、Bashなどでファイルへ保存して実行し、該当行の前後を読む(収集上限を超えた長いログでは、行番号は先頭側と末尾側それぞれの収集範囲内のもの)。
3. 抜粋が不十分と感じたら、抜粋だけで原因を断定せず、上記で原文を確認してから修正に入る。

## 制約と連携

完了報告そのものは止められず、モデルへの案内と通知で判定を守らせる。既存失敗の分類は終了コードの比較による近似。未追跡ファイルの内容ハッシュは最大500件で、Gitが無視するファイルは変更判定に含まれない。

[change-review](../change-review/README.md) へ検証結果を渡せる。[task-checkpoint](../task-checkpoint/README.md) のverifyは結果の記録であり、このツールの実行結果が自動転記されるわけではない。

## 設定

プラグイン設定の `userConfig` で次の項目を変更できる。既定値は [plugin.json](.claude-plugin/plugin.json) に定義されている。

| 項目 | 型 | 既定値 | 内容 |
|---|---|---|---|
| `defaultTimeoutSec` | number | `300` | 条件ごとにタイムアウトを指定しなかったときに使う。超えたコマンドは強制終了し、タイムアウトとして記録する 範囲: 5〜600。 |
| `outputTailChars` | number | `2000` | 失敗した検証コマンドの出力の末尾をこの文字数だけモデルへ返す。出力は保存しない 範囲: 0〜20000。LLM抽出の返却上限にも使う |
| `llmMode` | string | `off` | ローカルLLMによる失敗ログ抽出の利用モード。`off` / `auto` / `always` |
| `ollamaUrl` | string | `http://localhost:11434` | ollamaサーバーのベースURL |
| `models` | string | `tev1:4b,nimble` | 優先順のカンマ区切り。失敗したモデルは次へ回す |
| `timeoutSeconds` | number | `30` | 1モデルあたりのタイムアウト。範囲: 5〜120 |
| `totalTimeoutSeconds` | number | `60` | 全モデル合計の待ち時間の上限。範囲: 5〜600 |
| `maxAttempts` | number | `2` | 1回で試すモデルの最大数。範囲: 1〜10 |
| `keepAlive` | string | `1m` | ollamaのkeep_alive |
| `maxInputChars` | number | `12000` | LLMへ送る入力の上限。範囲: 500〜200000 |
| `maxOutputChars` | number | `4000` | LLMの応答の上限。超えた応答は不正として捨てる。範囲: 200〜100000 |
